# 구성요소 분해: transformer · Rocq · Screamer · Silicon

목적: 지금까지 "부품 이름" 수준(top-k attention, residual gate, register)으로 실험했고,
각 소스의 **어떤 원리**를 가져오는지 불명확했습니다. 여기서는 네 시스템을 구성요소로
쪼개고, 우리 구현과의 대응, 그리고 **어느 transformer 슬롯에 어떤 연역 원리가 들어갈 수
있는지**를 정리합니다. 수치는 0.0259–0.0269의 측정 상태입니다.

---

## 1. Transformer 분해 (8개 슬롯)

| 슬롯 | 결정하는 것 | 표현할 수 있는 것 / 없는 것 | 이 라인의 상태 |
|---|---|---|---|
| T1 입력 인코딩 | 무엇이 토큰이고 무엇이 특징인가 | 임의 특징은 표현 가능, 입력의 **관계 구조**는 사전에 손으로 넣어야 함 | 수치 특징 44/38, 위치 없음 |
| T2 어텐션 점수 | 어떤 쌍이 상호작용하는가 | 전 쌍 상호작용은 표현, **타입이 다른 상호작용**(사실↔후보↔의무)은 마스크 없이는 뒤섞임 | 단일 softmax, 타입 구분 없음 |
| T3 마스크/헤드 | 누가 누구를 볼 수 있는가 | causal/타입/경로 마스크 가능 | 없음 (SYMGATE는 잔차만) |
| T4 잔차·정규화 위상 | 최적화 안정성, 정보 흐름 | pre-LN은 안정, post-LN은 깊은 적층에 유리 | pre-LN, 2블록 |
| T5 FFN | 토큰별 비선형 가공 | 지역 패턴 | GELU 64, 변형 null |
| T6 readout/pooling | 출력을 어떻게 모으는가 | per-token 점수, pooled 벡터, max 혼합 | per-candidate 선형, 다중 레지스터 max(null) |
| T7 목적함수 | 무엇을 맞추는가 | 토큰 CE, listwise, pairwise, 보조 예측, 값 | listwise CE + pairwise, 라벨=커널 DP(비용 제거) |
| T8 상태 인터페이스 | 스텝 사이에 무엇이 전달되는가 | 무상태(정적 순위기) vs 잠재 재귀 | 정적 + 실험적 GRU 셀(null) |

핵심 관찰: **T1·T2·T3·T8이 연역 구조가 들어갈 자리**이고, T4·T5·T6은 대부분 최적화·용량
문제입니다. 지금까지의 null은 거의 전부 T4·T5·T6에서 나왔습니다.

## 2. Rocq 분해 (6개)

| 구성요소 | 원리 | 우리 대응 | 상태 |
|---|---|---|---|
| 커널(작은 신뢰 검사기) | 증명항을 독립 검사, 전술은 불신 | Horn 폐포 + 증명서(parent map) 재유도 | 있음. `CERT`는 답 보존, 변이 거부 81/81 |
| 전술(refinement) | 목표를 하위목표로 **분해** | 계약(2규칙 사슬) = 분해된 스텝 | 부분. 2단계까지 |
| 의무(goal stack) | 미해결 목표 집합을 상태로 유지 | goal 피처 + FOCUS | FOCUS는 d4/b4에서 **공허**(0 제거) |
| 보조정리 재사용 | 증명된 사실을 다음 증명에 재사용 | 계약 채굴/적용 | 있음, 최대 양성 |
| `assert`/cut | 중간 보조정리를 **스스로 발명** | 없음 | 미구현 |
| hint DB + `eauto` depth | 국소 탐색 정책 | rule_prior(상태 무관) | 상태 조건화 없음 |

## 3. Screamer 분해 (6개)

| 구성요소 | 원리 | 우리 대응 | 상태 |
|---|---|---|---|
| 선택점(either) | 분기를 값으로 다룸 | DFS branch, 다중 레지스터 토큰 | DFS 있음, 레지스터 null |

## 4. Silicon 분해 (6개)

| 구성요소 | 원리 | 우리 대응 | 상태 |
|---|---|---|---|
| 기호 상태(heap/store) | 사실 집합 + 엔티티 바인딩 | fact mask + (단항) 엔티티 | 단항이라 바인딩 자명 |
| 경로 조건(path condition) | 실행 경로의 논리 제약 | SYMGATE(후보 admissible) | 중립~음성 |
| 계약(pre/post) | 호출 지점 요약 | 2규칙 계약 | 있음, 최대 양성 |
| join | 분기 병합 시 상태 합집합 | 없음(definite fact의 합집합) | 미구현 |
| 권한/자원 회계 | 소비-생산 선형성 | 비용(cost)만 | 부분(라벨에서 제거됨) |
| SMT 위임 | 순수 논리 결정 | 커널 폐포 | 있음 |

## 5. 교차표: 연역 원리 → transformer 슬롯

| 원리(출처) | 들어갈 슬롯 | 필요한 새 부품 | 판별 실험 |
|---|---|---|---|
| 의무 분해 (Rocq 전술) | T2/T3 | **obligation 토큰 + 후보↔의무 타입 어텐션** | 관계형 fixture에서 FOCUS 재측정 |
| 보조정리 발명 (Rocq assert) | T7 | 모델이 atom 제안 → 커널 채택/거부율 | 거부율이 학습 지표 |
| hint 우선순위 (Rocq eauto) | T7/T6 | 상태 조건부 prior(현재는 전역 상수) | 상태 셔플 통제 |

## 6. 백지에서 다시 구성한다면 (참조는 참고만)

지금 구현은 "번역기 transformer를 집합 순위기로 축소"한 것입니다. 백지에서 증명 상태용으로
설계하면 다음이 달라집니다.

**버릴 것**: 위치 인코딩, causal mask, 어휘 임베딩/LM head, encoder–decoder 분리,
토큰 단위 CE.

**유지할 것**: scaled dot-product attention, residual, LayerNorm, FFN — 계산 프리미티브로서만.

**새로 넣을 것**:
1. **타입이 있는 토큰 3종**: 사실(fact), 후보(candidate), 의무(obligation). 각각 다른
   임베딩 경로를 갖고, 어텐션은 **타입쌍별로 다른 가중치**를 씁니다(candidate→fact는
   지지 관계, candidate→obligation은 관련성, obligation끼리는 독립).
2. **엔티티·역할 임베딩**: 위치 대신 "어느 엔티티가 어느 인자 위치를 채우는가"를 표현.
   단항 fixture에서는 자명하므로, 관계형에서만 의미가 생깁니다.
3. **의무 조건부 readout**: 후보 점수를 전역 문맥이 아니라 "지금 풀어야 할 의무"에 조건화.
4. **재귀는 정보가 있을 때만**: 0269에서 마르코프 충분 상태에서는 재귀가 null임을 확인.
   부분관측/대규모 세계에서만 z를 도입.
5. **출력은 순위 + 증거**: 점수와 함께 "어느 사실에 기댔는가"(attention mass)를 내고,
   커널이 그 증거로 검증. Silicon의 요약/계약 정신.

파라미터 예산은 현재와 같은 규모(2만 내외)로 유지해 비교 가능하게 합니다.

## 7. 실험 계획 (단순 3-arm 형식 유지)

```text
S0  현재 set transformer (기준)
S1  typed-attention 3토큰 구조 (사실/후보/의무, 타입쌍별 어텐션)
S2  S1 + 의무 조건부 readout
```

- 같은 라벨(커널 DP, 비용 제거), 같은 탐색(branch 5), 같은 예산, 5시드.
- 판별 예측: S1/S2가 S0를 넘으려면 **의무/사실 구분이 실제로 정보를 담아야** 합니다.
  단항 fixture에서는 사실 토큰이 후보 특징과 중복되므로 이득이 없을 것으로 **예측**합니다.
  따라서 S1/S2는 **관계형 fixture와 함께** 평가해야 판별력이 생깁니다.
- 게이트는 기존 것을 그대로 재사용: gradcheck+liveness, O0/O2/O3, ASan, 순열 등변,
  라벨 독립성, 표-재계산 동본, 열화 변이.

## 8. 정직한 경계

- 지금 확립된 것은 "라벨·행동공간을 연역 쪽으로 옮기면 학습 구조가 달라진다"입니다.
- 구조 변경(S1/S2, 루프 셀, all-values)은 이 fixture에서 **이득이 없을 것으로 예측**됩니다.
  이유는 정보 구조가 이미 충분하기 때문이고, 0269의 shuf 결과가 그 근거입니다.
- 그러므로 다음 단계의 순서는 **관계형 fixture → 구조 실험**입니다. 순서를 뒤집으면
  또 null을 쌓습니다.
